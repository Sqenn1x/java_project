# Jira Lite

Лёгкий веб-трекер задач на Java и Spring Boot. В проекте есть несколько пространств с разными шаблонами, Kanban-доска, список задач, спринты и AI-чат для помощи в работе с проектом.

> Это учебный прототип, вдохновлённый Jira, а не официальная Jira и не готовая к публичному production-развёртыванию система. Некоторые шаблоны задают оформление и начальное представление задач, но не включают весь набор специализированных сервисов Jira.

## Возможности

### Пространства и шаблоны

Можно создавать отдельные пространства и переключаться между ними. Доступны шаблоны:

| Шаблон | Для чего подходит |
|---|---|
| Personal task planner | Личные задачи, сроки и приоритеты |
| General service management | Единый поток обращений для поддержки |
| Development requests | Запросы на разработку, функции, ошибки и инциденты |
| Kanban | Непрерывный поток задач по статусам |
| Project management | Планирование и выполнение проектов |
| Scrum | Бэклог и работа спринтами |

У пространства можно задать название, ключ и тип управления. Выбранный шаблон сохраняется вместе с пространством. Для Development requests предусмотрен отдельный экран «Вся работа» с поиском, фильтрацией и группировкой.

### Задачи

- Создание, редактирование и удаление задач.
- Типы: задача, история, ошибка, эпик и подзадача.
- Приоритеты: низкий, средний, высокий и критический.
- Статусы Kanban: к выполнению, в работе, на ревью и готово.
- Просмотр задач на доске и в списке; календарный таймлайн для дат.
- Назначение задачи текущему пользователю, сроки и описание.
- Комментарии и загрузка файлов размером до 10 МБ.

### Scrum

- Создание спринтов с целью и датами.
- Просмотр задач в бэклоге.
- Запуск и завершение спринта.

### AI-помощник

- Плавающий чат с сохранением переписки.
- История загружается при повторном открытии чата; её можно очистить.
- AI-помощник может выполнять поддерживаемые действия с пространствами, задачами, спринтами, комментариями и текстовыми вложениями.
- Для работы с AI необходим API-ключ Google Gemini.

### Автоматизация

В интерфейсе можно создавать простые правила, реагирующие на смену статуса задачи, например менять приоритет или назначать её текущему пользователю. Правила и журнал аудита сохраняются в `localStorage` браузера для текущего пользователя и пространства — они не синхронизируются между устройствами.

## Быстрый запуск

1. Клонируйте репозиторий и перейдите в каталог проекта:

   ```powershell
   git clone https://github.com/Sqenn1x/java_project.git
   cd java_project
   ```

2. Создайте базу данных MySQL:

   ```sql
   CREATE DATABASE jira_lite CHARACTER SET utf8mb4;
   ```

3. Проверьте параметры подключения в `src/main/resources/application.properties`. По умолчанию проект подключается к `localhost:3306`, базе `jira_lite` и пользователю `root`. Если у пользователя есть пароль или другие реквизиты, настройте их в конфигурации.

4. При необходимости задайте API-ключ Gemini в PowerShell. Не вставляйте ключ в исходный код или Git:

   ```powershell
   $env:GEMINI_API_KEY = "ваш-ключ"
   ```

   Если ключ не задан, приложение запускается, но AI-функции работать не будут.

5. Запустите приложение:

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

6. Откройте в браузере [http://localhost:8080](http://localhost:8080).

Hibernate создаёт и обновляет таблицы автоматически благодаря `spring.jpa.hibernate.ddl-auto=update`. Для production вместо автоматического обновления схемы рекомендуется использовать управляемые миграции.

## Настройки

Основные параметры находятся в `src/main/resources/application.properties`:

| Параметр | Назначение |
|---|---|
| `spring.datasource.url` | Адрес и параметры подключения к MySQL |
| `spring.datasource.username` | Пользователь MySQL |
| `spring.jpa.hibernate.ddl-auto` | Автоматическое обновление схемы |
| `spring.servlet.multipart.max-file-size` | Максимальный размер одного загружаемого файла |
| `spring.servlet.multipart.max-request-size` | Максимальный размер multipart-запроса |
| `gemini.model` | Имя модели Gemini |
| `gemini.api.key` | Берётся из переменной окружения `GEMINI_API_KEY` |

Чтобы временно задать ключ для текущего сеанса PowerShell:

```powershell
$env:GEMINI_API_KEY = "ваш-ключ"
.\mvnw.cmd spring-boot:run
```

Для постоянного использования задайте переменную окружения в настройках операционной системы или используйте локальный, не добавленный в Git конфигурационный файл.

## Использование

1. Зарегистрируйтесь или войдите по email.
2. Создайте пространство и выберите подходящий шаблон.
3. Добавляйте задачи через кнопку создания или с помощью AI-чата.
4. Перемещайте задачи по статусам на Kanban-доске либо работайте со списком.
5. Для Scrum-шаблона создавайте спринты и распределяйте по ним задачи.
6. Откройте меню с молнией, чтобы настроить автоматизацию.

## HTTP API

Базовый префикс API: `/api`.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/users/register` | Регистрация |
| `POST` | `/users/login` | Вход по email |
| `GET` | `/boards?userId={id}` | Получить пространства пользователя |
| `POST` | `/boards` | Создать пространство |
| `GET` | `/tasks?userId={id}&boardId={id}` | Получить задачи пространства |
| `POST` | `/tasks` | Создать задачу |
| `GET` | `/tasks/{taskId}` | Получить задачу |
| `PUT` | `/tasks/{taskId}` | Изменить задачу |
| `DELETE` | `/tasks/{taskId}` | Удалить задачу |
| `GET`, `POST` | `/tasks/{taskId}/comments` | Получить или добавить комментарий |
| `GET`, `POST` | `/tasks/{taskId}/attachments` | Получить или загрузить вложение |
| `GET`, `DELETE` | `/tasks/{taskId}/attachments/{attachmentId}` | Скачать или удалить вложение |
| `GET`, `POST` | `/boards/{boardId}/sprints` | Получить или создать спринт |
| `POST` | `/boards/{boardId}/sprints/{sprintId}/start` | Запустить спринт |
| `POST` | `/boards/{boardId}/sprints/{sprintId}/complete` | Завершить спринт |
| `GET`, `DELETE` | `/ai/history?userId={id}` | Получить или очистить историю AI-чата |
| `POST` | `/ai/command` | Отправить AI-команду |

Для запросов, требующих JSON-тела, передавайте `Content-Type: application/json`. Загрузка вложений выполняется как `multipart/form-data` с полем `file`.

## Тесты

Тесты используют H2 и не требуют отдельного сервера MySQL:

```powershell
.\mvnw.cmd test
```

Собрать JAR:

```powershell
.\mvnw.cmd clean package
```

Запустить собранное приложение:

```powershell
java -jar .\target\jira_lite-1.0.0.jar
```

## Ограничения и безопасность

- Проект предназначен для разработки и демонстрации. Перед публикацией в интернете настройте полноценную аутентификацию и авторизацию, HTTPS, CORS и защиту API.
- Текущий вход проверяет существование email и не является полноценной системой защиты аккаунтов.
- Часть API принимает `userId` от клиента; не считайте его достаточным механизмом авторизации для недоверенной сети.
- Автоматизации хранятся локально в браузере, а не в базе данных.
- Некоторые шаблоны пока используют общий набор задач и операций. Название и представление шаблона не означают наличие всех специализированных процессов Jira Service Management или Jira Software.
- Не коммитьте API-ключи, пароли и другие секреты. Если секрет уже попадал в Git или переписку, отзовите его и создайте новый.
